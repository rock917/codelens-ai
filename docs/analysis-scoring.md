# Analysis scoring and scan states

Static analysis supports Python, limited JavaScript/TypeScript patterns, Java, Go, C++, and valid Python notebook cells. JSON is validated separately, not scored. Repository ingestion indexes code; a separate scan produces findings. An unrun scan has no health score. Unparseable Python/compiled source is excluded with a coverage notice, never presented as clean scanned code.

The risk-density-v2 score counts only the security-risk rules, HIGH_COMPLEXITY and DEEP_NESTING explicitly listed in `scoring_policy.py`. Long lines are no longer detected, and historical LONG_LINE/WEAK_JWT_ALG records are hidden from current analysis results. TODOs, debug prints, unused imports, empty functions, and size/parameter/method-count heuristics remain suggestions with no score penalty. Unknown future rule types default to suggestions until deliberately added to the scoring policy.

Scored findings are weighted critical=15, high=8, medium=3, low=1. Weighted density is the sum of weights multiplied by 1,000 and divided by max(1,000, scanned lines). Score = round(100 / (1 + density / 20)). Only critical security findings cap the score at 49 and high security findings at 79; complexity alone does not invoke a security cap. This is a review-prioritization heuristic, not a security certification or proof of a vulnerability. Review context and scan coverage alongside every score.

Python credential checks examine literal assignments, not comments or text mentioning credentials. Explicit placeholder values are ignored; other credential-like literals are review findings (HIGH), not confirmed exposed secrets. Hash checks require calls to known legacy hash APIs; `usedforsecurity=False` is excluded. HS256 alone is not a weak-algorithm finding. Subprocess argument lists without a shell are not command-injection findings. Dynamic commands passed to a shell and dynamic inline SQL reaching execute/executemany are flagged. These are limited syntax checks, not full symbol resolution or taint analysis; variable-based SQL and unknown wrappers may not be detected. JS/TS checks remain limited textual literal/call patterns and can have false positives. Java/Go/C++ use their existing syntax checks.

Python complexity excludes nested callable bodies from the parent, and an elif chain is not counted as increasingly deep nesting. New scans record the policy version in existing coverage metadata. Policy and analyzer source fingerprints invalidate saved scan caches. A normal Run Analysis refreshes older results without using an import credit.

`total_issues`, `by_severity`, `by_type`, repository `issues_count`, and dashboard counts now represent scored findings. `total_suggestions` and `total_findings` are separate. The issue list includes `affects_health` and `score_reason`; the UI defaults to Health findings and offers Suggestions and All findings. Old stored records are reclassified on read; `requires_rescan` flags older detector results until refreshed. There is no schema migration or bulk rewrite of saved findings. Existing data exports remain faithful copies of stored findings; rescanning replaces old records transactionally.

Scans use existing repository_jobs rows (job_type ANALYSIS), so no schema migration is needed. The PostgreSQL repository row lock serializes scan creation for a repository. Background scans own their database sessions and run file/AST work off the event loop. Results are replaced in a single transaction. Failures retain the previous successful results; missing source files cause failure, not a clean score. A completed scan with no supported files has no score. Startup recovery marks interrupted scans failed on the supported single-worker deployment.
